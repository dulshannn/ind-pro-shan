Problem Statement

Why Was This Built?

Shan Auto Lanka operated with manual, paper-based processes causing significant inefficiencies.

⚠️ Existing Challenges

  • No centralised inventory for vehicles & spare parts
  • Customer inquiries handled via phone/walk-in only
  • Zero visibility into sales orders and revenue
  • No online presence or product catalog
  • Staff access not controlled — data security risk
  • No online payment capability

✅ Proposed Solution

  • Digital platform with public-facing catalog & shop
  • Customer self-service: orders, payments & inquiries
  • Admin & manager dashboards for real-time OPS
  • Role-based access control (RBAC) for staff security
  • PayHere payment gateway integration
  • Automated CSV report generation

Security

Role-Based Access Control (RBAC)

Dynamic, granular permission system securing every module and API route.

🔴 Super Admin
  • Full system access
  • Manage all users & roles
  • Assign granular permissions to managers

Payment Gateway

PayHere Integration

Secure online payments via PayHere — Sri Lanka's leading payment gateway.

1
Customer Proceeds to Checkout
After reviewing cart, clicks "Pay Now" — PayHere form initialised with order details.
2
PayHere Hosted Page
Customer completes payment on PayHere's secure page. Visa, Mastercard, local banks supported.
3
Server-to-Server Callback
PayHere POSTs a signed notify_url to Express backend — cannot be forged by browser.
4
Order Confirmed as Paid
Backend verifies MD5 hash, updates order status to "Paid" in MongoDB. Customer sees confirmation.

🔐 MD5 Hash Verification

Every callback validated using merchant_secret + order_id + amount hash. Prevents forged payments from marking orders as paid.

💳 Supported Methods

Visa · Mastercard · AMEX · Internet Banking (HNB, BOC, Sampath) · Frimi · eZ Cash · mCash

🧪 Sandbox Testing

PayHere Sandbox used during development for safe simulation of full payment cycles without real transactions.

Journey

Challenges & How I Solved Them

Real engineering problems encountered and resolved during development.

🔐 Manager Login Authentication Bug

Managers couldn't log in due to bcrypt round mismatch in the seed script. Fixed by standardising bcrypt rounds and verifying the JWT payload correctly carries the permissions array.

🧭 Dynamic Sidebar Routing

Sidebar showed all menu items regardless of role. Refactored Sidebar.jsx to read from AuthContext and conditionally render only links matching the user's permissions array.

🛡️ Static Role → Dynamic Permissions

Replaced a single isManagerOrAdmin check with a flexible requirePermission('module') factory function — granular per-module access with zero code changes needed.

💳 PayHere Callback Security

Ensuring callbacks were genuine required MD5 hash verification on the backend using merchant_secret + order_id + amount — preventing forged payment notifications.
